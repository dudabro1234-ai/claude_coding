# 수정 내역 (2026-07-08)

피드백 3건에 대한 원인 분석 및 수정. **전사 비용모델(Check/Greedy)은 원본
Check_251020.py / Greedy_251020.py와 수치 완전 일치(오차 < 1e-9)를 유지**하며,
그리디 최적화 결과는 최초 소스코드 실행 결과와 동일하게 보존된다.

## 1. 사업장 배분 편중 (특정 사업장 배분 0)

원인 3가지를 수정 (core/config.py, core/engine.py):

- **사이트 정의를 실데이터 형식(A=이천 / B=청주 / C=용인)으로 변경.**
  구버전 IC/CJ/YI 코드로는 Portfolio_251020 형식 CSV의 컬럼을 찾지 못했음.
  전력량요금 컬럼은 UC_A/UC_B/UC_C와 UC_IC/UC_CJ/UC_YI 두 형식 모두 자동 인식.
- **망이용요금 단위 버그 수정** (`cost_site`): 계약용량(kW 환산)과 Peak_Min(MW 원값)을
  직접 비교하던 것을 동일 단위(kW)로 통일. 기존에는 Peak_Min이 사실상 0으로 취급되어
  어느 사업장에 배분해도 망이용요금이 같아져 분산 유인이 소멸했음.
- **회사 RE 필요량을 3개 사업장 합산으로 수정** (`_company_cost_across_sites`):
  기존 원본은 첫 사업장(A) 필요량만 사용 → EAC 비용 과소평가·배분 왜곡.
- **동률 타이브레이크 개선** (`run_site`): 절감액이 사실상 동률이면 수요 여유
  (사업장 사용량 − 배분된 RE 발전량)가 큰 사업장을 우선. 기존 strict 비교는
  항상 첫 사업장이 동률을 독식해 특정 사업장 배분 0이 발생했음.

수정 후 실데이터 2050년 배분: A 1,800 / B 7,318 / C 2,570 MW (합계 11,688 MW 동일).
B(청주) 비중이 큰 것은 전력량요금 단가(UC_CJ)가 최고라 회피 효과가 가장 크기 때문 —
모델의 경제적 판단이며 버그 아님.

## 2. RE100 달성경로 목표선 100% 초과

원인: 차트 분모가 실제 연간 수요(SKH)가 아닌 **비용모델용 프록시(Peak_Min×8760)**였음.
샘플 데이터는 두 값이 우연히 일치했으나, 실데이터는 SKH가 최대 2.8배 커서
target%가 goal%보다 부풀려져 100%를 초과했음.

수정 (server.py `_compute_run_uncached`): re_path의 분모를 RE 조달현황의
"전체 수요"(실제 연간 사용량)로 교체. 이제 target% = RE Goal%와 정확히 일치
(실데이터 2050년 77.0%). **비용모델 내부의 Peak_Min 프록시는 원본 설계이므로
변경하지 않음** — 그리디 결과 보존을 위한 의도적 결정.

## 3. 발전원 믹스 선 겹침 ("동일하게 나옴")

원인: 계산 오류가 아니라 차트 표현 문제. 누적(stacked) 라인 방식에서 용량 0인
발전원의 선이 바로 아래 발전원 선과 완전히 겹침 (해상풍력은 2045년 이전 육상풍력과,
균등태양광은 2042년 이전 수력과 일치하게 보였음).

수정 (web/index.html `drawMix`): 누적 라인 → **스택 바 차트**로 변경.
발전원별 원값(MW)을 쌓아 표시하고 툴팁에서 개별 값 확인 가능.
RE 경로 차트의 y축 100% 상한도 제거 (PPA 잉여발전 시 100% 초과 표시 가능).
