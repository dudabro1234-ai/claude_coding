# RE100 PPA 시스템 — 입력 데이터 명세서

> 기존 `Greedy / Check / Site` 3개 파이썬 코드를 역분석하여, **각 CSV 파일이 반드시 가져야 하는 컬럼**을 정리한 문서입니다.
> 사내 데이터 담당자는 이 명세에 맞춰 4종 CSV를 준비하면, 코드 수정 없이 그대로 실행할 수 있습니다.

---

## 0. 공통 규칙

| 항목 | 규칙 |
|------|------|
| 파일 인코딩 | UTF-8 (한글 컬럼명이 있으므로 **UTF-8 권장**) |
| 파일 위치 | 4종 CSV는 같은 폴더에 두고, 실행 시 해당 폴더를 지정 |
| 연도 범위 | **2026 ~ 2050년** (25개 연도) 모두 존재해야 함 |
| 컬럼명 매칭 | 코드가 컬럼명을 찾을 때 **대소문자·공백·하이픈을 무시**하고 매칭함. 단, 철자 자체는 정확해야 함 |
| 결측치 | 비워두지 말 것 (계산 중 NaN 전파 위험). 없으면 0으로 채움 |

> ⚠️ **발견된 코드 불일치:** `Site.py`는 전력량요금을 `UC_IC/CJ/YI` 컬럼에서, `Check/Greedy`는 `VC_M` 컬럼에서 읽습니다. 또 사용량도 `Site`는 `IC/CJ/YI`(사업장별), `Check/Greedy`는 `SKH`(전사)를 씁니다. **현재 단계의 샘플 데이터에는 양쪽 컬럼을 모두 포함**시켜 어느 코드로도 돌아가게 합니다. (2단계 공통 엔진화에서 이 불일치를 정리할 예정)

## 1. `Hourly_Data.csv` — 시간별 발전 패턴 / SMP

연도별 8,760시간(365일 × 24시간)의 시간별 데이터. **행 수 ≈ 25년 × 8,760 = 219,000행**

| 컬럼명 | 타입 | 단위/범위 | 설명 | 사용 모듈 |
|--------|------|-----------|------|-----------|
| `Year` | int | 2026~2050 | 연도 (연도별 그룹화 기준) | 전체 |
| `Month` | int | 1~12 | 월 (월별 평균 집계용) | Check |
| `Day` | int | 1~31 | 일 (상세 시트 출력용) | Check |
| `Hour` | int | 0~23 | 시각 (시간별 평균 집계용) | 전체 |
| `PV_GENERATION_2` | float | 0.0~1.0 | 태양광 시간별 발전계수 (낮 양수, 야간 0) | 전체 |
| `WT_GENERATION` | float | 0.0~1.0 | 풍력 시간별 발전계수 (육상·해상 공용) | 전체 |
| `SMP` | float | 원/kWh | 시간별 계통한계가격 | 전체 |
| `Factor_ADJ` | float | 0.7~1.4 | 전력량요금 계절·시간 조정계수 | Check / Greedy |
| `고압B 선택2` | float | 0.7~1.4 | **IC(이천)** 요금 조정계수 | Site |
| `고압B 선택3` | float | 0.7~1.4 | **CJ(청주)** 요금 조정계수 | Site |
| `고압C 선택2` | float | 0.7~1.4 | **YI(용인)** 요금 조정계수 | Site |

- 발전량 계산식: `시간별 발전량(MWh) = 설비용량(MW) × 이용률 × 발전계수 × 효율감소`
- 이용률은 코드 상수: 태양광 15%, 육상풍력 25%, 해상풍력 35%, 수력 26%, SMR 90%
- 수력·SMR·균등태양광·균등풍력은 발전계수 컬럼 없이 **균등(상수 1.0)** 으로 처리됨

## 2. `Annual_Usage.csv` — 연도별 사용량 / 피크 / RE 목표

연도별 1행. **숫자에 천단위 콤마(`,`)가 있어도 됨** (코드가 `thousands=','`로 읽음)

| 컬럼명 | 타입 | 단위 | 설명 | 사용 모듈 |
|--------|------|------|------|-----------|
| `Year` | int | 2026~2050 | 연도 | 전체 |
| `SKH` | float | MWh | **전사** 연간 전력 사용량 | Check / Greedy |
| `SKH_Peak` | float | MW | 전사 기본요금 산정용 피크 | Check / Greedy |
| `SKH_Peak_Min` | float | MW | 전사 망이용요금 기준 + 시간당 사용량 기준 | Check / Greedy |
| `IC` / `CJ` / `YI` | float | MWh | **사업장별** 연간 사용량 (이천/청주/용인) | Site |
| `IC_PEAK` / `CJ_PEAK` / `YI_PEAK` | float | MW | 사업장별 기본요금용 피크 | Site |
| `IC_Peak_Min` / `CJ_Peak_Min` / `YI_Peak_Min` | float | MW | 사업장별 망이용요금 기준 | Site |
| `SEC` | float | MWh | SEC 수전량 (RE 조달 현황 출력용) | Check |
| `RE33` | float | 0.0~1.0 | RE 목표 비율 — SEC 가동중단 기준 | (시나리오) |
| `RE33_SEC` | float | 0.0~1.0 | RE 목표 비율 — **SEC 계속가동 기준 (기본값)** | 전체 |
| `RE44` | float | 0.0~1.0 | RE 목표 비율 — 대안 시나리오 | (시나리오) |
| `RE44_SEC` | float | 0.0~1.0 | RE 목표 비율 — 대안 시나리오 | (시나리오) |

- `re_goal_column` 파라미터로 위 4개 중 하나를 선택 (기본 `RE33_SEC`)
- RE 목표량(MWh) = `연간 사용량 × RE 목표 비율`

## 3. `Annual_PPA.csv` — 발전원별 연도별 PPA 단가

연도별 1행. 단가 시나리오는 `M`(중간) 기준.

| 컬럼명 | 타입 | 단위 | 설명 | 적용 발전원 |
|--------|------|------|------|-------------|
| `Year` | int | 2026~2050 | 연도 | — |
| `PV_M` | float | 원/kWh | 태양광 PPA 단가 | 태양광 / 균등태양광 |
| `On_W_M` | float | 원/kWh | 육상풍력 PPA 단가 | 육상풍력 / 균등풍력 |
| `Off_W_M` | float | 원/kWh | 해상풍력 PPA 단가 | 해상풍력 |
| `HP_M` | float | 원/kWh | 수력 PPA 단가 | 수력 |
| `SMR_M` | float | 원/kWh | SMR PPA 단가 | SMR |

- 계약 단가는 **체결 연도(vintage) 기준**으로 고정되며, 20년 경과 시 기준연도가 갱신됨
- 따라서 2026~2050 모든 연도의 단가가 채워져 있어야 함

---

## 4. `Annual_Rate.csv` — 한전 요금 단가 / SMP 기준

연도별 1행. 요금 시나리오는 `M`(중간) 기준.

| 컬럼명 | 타입 | 단위 | 설명 | 사용 모듈 |
|--------|------|------|------|-----------|
| `Year` | int | 2026~2050 | 연도 | 전체 |
| `VC_M` | float | 원/kWh | 전력량요금 (variable) | Check / Greedy |
| `FC_M` | float | 원/kWh | 기후환경요금 + 연료비조정요금 | 전체 |
| `BC_M` | float | 원/kW | 기본요금 단가 (월) | Check / Greedy |
| `EAC_M` | float | 원/kWh | EAC(단기 이행수단) 단가 | 전체 |
| `SMP_M` | float | 배수 | SMP 기준 배수 (보통 1.0) | 전체 |
| `UC_IC` / `UC_CJ` / `UC_YI` | float | 원/kWh | **사업장별** 전력량요금 (이천/청주/용인) | Site |

> Site는 기본요금을 코드 내 상수(IC 7,380 / CJ 8,190 / YI 7,520 원/kW)로 처리하므로, `BC_M`은 Check/Greedy 전용입니다.

## 4-1. 기준정보 시나리오 확장 (선택 사항)

기준정보를 시나리오별로 분류해 **2(사용량) × 2(PPA단가) × 3(SMP) = 최대 12개 case**를 테스트할 수 있습니다.

> ✅ **하위 호환:** 아래 시나리오 데이터는 전부 **선택 사항**입니다. 기존 4종 CSV만 있으면
> 각 축에 기본안 하나만 노출되며, 이전 버전과 완전히 동일하게 동작합니다.
> 시나리오 데이터를 추가하는 즉시 대시보드에 선택지가 자동으로 나타납니다 (코드 수정 불필요).

| 축 | 시나리오 | 입력 방법 | 없을 때 |
|----|----------|-----------|---------|
| 사업장 사용량 | `base` (기본) | `Annual_Usage.csv` (기존 그대로) | — |
| | `worst` | **`Annual_Usage_worst.csv`** — 기존 파일과 동일한 컬럼 구조로 같은 폴더에 추가 | base만 노출 |
| PPA 단가 | `fixed` 고정(현행) | 기존 `PV_M`, `On_W_M` … 컬럼 | — |
| | `variable` 연도별 변동 | `Annual_PPA.csv`에 **`PV_V`, `On_W_V`, `Off_W_V` …** 컬럼 추가 | fixed만 노출 |
| SMP | `M` 기본안 | 기존 `SMP_M` 배수 컬럼 | 배수 1 처리 |
| | `H` 고가 / `L` 저가 | `Annual_Rate.csv`에 **`SMP_H` / `SMP_L`** 배수 컬럼 추가 | 기본안만 노출 |

세부 규칙:

- **PPA 변동 단가의 발전원별 폴백:** `*_V` 컬럼이 일부 발전원에만 있어도 됩니다(예: 태양광·풍력만).
  V 컬럼이 없는 발전원(수력·SMR 등)은 자동으로 `*_M`(고정) 단가를 사용합니다.
- **SMP 시나리오는 배수 곡선**입니다. 시간별 SMP 패턴(`Hourly_Data.csv`)은 시나리오 공통이고,
  연도별 배수(`SMP_H`/`SMP_L`)만 곱해집니다. → **발전패턴 동일** 원칙 유지.
- `Annual_Usage_worst.csv`는 `Annual_Usage.csv`와 **완전히 같은 컬럼**(사용량·피크·RE목표)을 가져야 합니다.
- 시나리오 선택은 대시보드 좌측 "기준정보 시나리오" 패널에서 하며,
  "시나리오 매트릭스" 카드에서 존재하는 모든 조합을 일괄 계산·비교할 수 있습니다.

데모 데이터: `python tools/generate_scenario_data.py` 를 실행하면 `data/sample`을 바탕으로
12개 조합이 모두 채워진 `data/sample_scenario/` 폴더가 생성됩니다.
(`PPA_DATA_DIR=data/sample_scenario python server.py` 로 실행)

## 5. 준비 체크리스트

사내에서 실제 데이터를 채울 때 확인:

- [ ] 4개 CSV 파일이 모두 같은 폴더에 있는가
- [ ] 모든 파일에 2026~2050년이 빠짐없이 있는가
- [ ] `Hourly_Data.csv`가 연도별 8,760행을 가지는가
- [ ] 한글 컬럼명(`고압B 선택2` 등)이 정확히 일치하는가
- [ ] RE 목표 비율(`RE33_SEC` 등)이 0~1 사이 소수인가 (33%면 0.33)
- [ ] 빈 칸(결측치) 없이 채워져 있는가
- [ ] 파일이 UTF-8로 저장되었는가
