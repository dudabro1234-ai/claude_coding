# RE100 PPA Simulator — 사내 k8s 배포 가이드

> 대상: Windows 10 빌드 PC + 사내 Docker 레지스트리 + 사내 k8s 클러스터
> 팀 내부용(동시 5명 이하), 접근제어 없음, 데이터 갱신 연 2~3회

---

## 이번 개선에서 바뀐 것 (요약)

| 항목 | 변경 내용 |
|---|---|
| server.py | ① 브라우저 자동 오픈 제거 ② 포트 환경변수 `PPA_PORT` 지원 ③ `/health` 엔드포인트 추가 ④ 데이터 캐시를 파일 수정시각(mtime) 기반으로 변경 → **CSV 교체만 하면 재시작 없이 자동 반영** |
| agent.py | `llm_config.json` 저장 경로를 `PPA_LLM_CONFIG_PATH` 환경변수로 지정 가능 → 컨테이너 재시작/재배포 후에도 LLM 설정 유지 |
| web/index.html | API 호출을 상대경로로 변경 → 경로 기반 Ingress(`/ppa/` 등) 하위에 붙여도 동작 |
| 신규 | `Dockerfile`, `requirements-docker.txt`, `entrypoint.sh`, `deploy/k8s.yaml` |
| 기존 로직 | 엔진(core)·화면(web)·AI 로직은 **변경 없음**. 로컬 실행(`python server.py`)도 기존과 동일하게 동작 |

## 1. 이미지 빌드 & 푸시 (빌드 PC에서)

```
cd ppa-dashboard

docker build -t docker-repo.skhynix.com/esg/ppa-dashboard:1.0.0 ^
  --build-arg BASE_REGISTRY=dockerhub.skhynix.com ^
  --build-arg PIP_INDEX_URL=http://<사내미러주소>/simple ^
  --build-arg PIP_TRUSTED_HOST=<사내미러주소> .

docker push docker-repo.skhynix.com/esg/ppa-dashboard:1.0.0
```

- `<사내미러주소>`: 사내 pip 미러(Nexus/Artifactory) 주소로 교체
- 이미지 경로의 `esg/` 부분은 팀에 할당된 레포지토리 경로에 맞게 수정

## 2. k8s 배포

```
kubectl apply -f deploy/k8s.yaml   # default 네임스페이스
```

배포 전 채워야 할 것:
1. **claimName** — 별도 위치에서 관리되는 실제 PVC 이름으로 교체 (매니페스트 주석 참고)
2. **Ingress** — 매니페스트 하단의 주석 템플릿을 해제하고 도메인/경로/클래스명 입력.
   앱이 상대경로로 동작하므로 rewrite 없이 `path: /ppa` prefix만으로 동작.
   단, **접속 시 경로 끝에 슬래시 필수** (`http://<도메인>/ppa/` — `/ppa`로 접속하면 화면 깨짐).
   슬래시 문제를 원천 차단하고 싶으면 템플릿의 [방식 2] rewrite 사용

배포 확인:
```
kubectl get pods -l app=ppa-dashboard
kubectl logs deploy/ppa-dashboard
```
→ 접속 URL에서 `/health` 가 `{"status": "ok"}` 이면 정상.

## 3. 실데이터 CSV 교체 (연 2~3회)

최초 배포 시에는 샘플 데이터로 동작합니다. 실데이터 반영:

```
kubectl cp Hourly_Data.csv   <파드이름>:/data/input/
kubectl cp Annual_Rate.csv   <파드이름>:/data/input/
kubectl cp Annual_Usage.csv  <파드이름>:/data/input/
kubectl cp Annual_PPA.csv    <파드이름>:/data/input/
```

- **재시작 불필요** — 다음 요청부터 자동으로 새 데이터 로드
- 파일은 PVC에 저장되므로 파드가 재시작돼도 유지됨
- CSV 형식은 `docs/DATA_SPEC.md` 참고

## 4. 사내 LLM 설정

배포 후 대시보드 우상단 **⚙ 설정**에서 Base URL / API Key / Model 입력 → 저장.
설정은 `/data/llm_config.json`(PVC)에 저장되어 재시작 후에도 유지됩니다.

환경변수로 고정하고 싶으면 Deployment env에 추가:
```yaml
- name: PPA_LLM_BASE_URL
  value: "http://<사내LLM주소>/v1"
- name: PPA_LLM_API_KEY
  valueFrom:
    secretKeyRef: { name: ppa-llm-secret, key: api-key }   # 평문 노출 방지 권장
- name: PPA_LLM_MODEL
  value: "<모델명>"
```

## 5. 운영 메모

- **replicas는 1 고정**: LLM 설정이 파일 기반이고 볼륨이 RWO라 다중 파드 불가. 5명 규모에는 충분
- **버전 업데이트**: 새 태그(1.0.1 등)로 빌드·푸시 후 `kubectl set image deploy/ppa-dashboard app=<새이미지>` 또는 매니페스트 수정 후 재적용
- **API 키 주의**: 접근제어가 없으므로 대시보드 접속자는 누구나 ⚙설정을 볼 수 있음. 팀 외부에 URL을 공유하지 말 것 (추후 필요 시 접근제어를 다음 단계로 추가)
