# 고객 ESG 대응 Agent

고객사로부터 수신되는 ESG 요구사항 메일을 자동 수집·구조화하고,
사내 Factsheet 기반 **1차 답변 초안**, **타부서 데이터 요청 초안**,
**답변 리스크 검토**를 생성하는 도구입니다.

> ⚠️ **이 도구는 어떤 메일도 자동으로 발송하지 않습니다.**
> 모든 초안은 Outlook 임시보관함에 저장만 되며, 최종 검토와 발송은 사용자가 직접 수행합니다.

## 처리 흐름

```
Outlook 지정 폴더 → ① 수집(collector) → ② 사내 LLM 분석(analyzer) → ③ 산출물(reporter)
                                                                       ├─ output/report_YYYYMMDD.html (검토 대시보드)
                                                                       ├─ output/tracker.xlsx (누적 관리대장)
                                                                       └─ Outlook 임시보관함 초안 (저장만)
```

검토 대시보드는 요구사항마다 다음 흐름으로 정리해 보여줍니다:

> **① 어떤 요청이 언제 왔는가** (수신일시·마감일·D-day·긴급도)
> → **② 우리가 가진 정보는 무엇인가** (Factsheet 매칭 값·단위·기준연도·출처)
> → **③ 어떤 내용으로 답변하는가** (답변 초안 / 부서요청 초안, 복사 버튼)
> → **④ 그렇게 답변하면 어떤 리스크가 있는가** (심각도별 리스크 검토 + 권고 대응)

- 원본 메일은 **절대 변경하지 않습니다** (읽음처리 X, 이동 X, 삭제 X).
- LLM 호출은 **사내 엔드포인트로만** 이루어집니다 (표준 라이브러리 `urllib` 사용, 외부 API 없음).
- Factsheet의 `public_yn = N`(대외비) 행은 변환 단계에서 원천 제외되어 LLM에 전달되지 않습니다.

## 설치 (Windows 업무 PC)

1. Python 3.10+ 설치 확인: `python --version`
2. 패키지 설치:
   ```
   pip install pywin32 openpyxl python-dateutil
   ```
3. Outlook 데스크톱 앱이 설치·로그인되어 있어야 합니다.

## 초기 설정

### 1) LLM 접속 정보 (`llm_config.json`)

`llm_config.example.json`을 **같은 폴더에 `llm_config.json`이라는 이름으로 복사**한 뒤
사내 LLM 정보를 입력합니다. 이 파일은 `.gitignore`에 등록되어 있어 커밋되지 않습니다.

```json
{ "base_url": "http://사내LLM주소/v1", "api_key": "발급받은 키", "model": "glm-5.2" }
```

환경변수(`ESG_LLM_BASE_URL`, `ESG_LLM_API_KEY`, `ESG_LLM_MODEL`)가 있으면 파일보다 우선합니다.

### 2) 업무 설정 (`config.json`) — 항목별 상세 설명

#### `outlook.folder_path` — 수집 대상 **Outlook 메일 폴더** 경로

**로컬 PC의 파일 폴더(C:\\...)가 아닙니다.** Outlook 앱 왼쪽 폴더 트리에 보이는
**메일 폴더의 경로**를 `/`로 이어서 적는 것입니다.

| Outlook 폴더 트리 모양 | folder_path 설정값 |
|---|---|
| 받은편지함 바로 아래 `ESG요청` 폴더를 만든 경우 | `"받은편지함/ESG요청"` |
| 받은편지함 → `고객사` → `ESG` 순서로 만든 경우 | `"받은편지함/고객사/ESG"` |
| 별도 폴더 없이 받은편지함 전체를 스캔하려는 경우 | `"받은편지함"` |

- 영문 Outlook이면 `"Inbox/ESG요청"`처럼 실제 표시 이름 그대로 적으세요.
- ESG 메일이 받은편지함에 섞여 들어온다면, Outlook의 **규칙(홈 → 규칙 → 규칙 만들기)**으로
  "특정 발신 도메인 → ESG요청 폴더로 이동"을 먼저 설정해 두는 방식을 권장합니다.
  (규칙이 없어도 동작은 하지만, 받은편지함 전체를 스캔하면 무관한 메일까지 LLM 분석 대상이 됩니다.)

#### `outlook.mailbox` — 메일 계정 이름 (대부분 빈칸)

- Outlook에 계정이 하나면 **빈 문자열 `""` 그대로** 두세요. 기본 계정을 사용합니다.
- 회사 계정과 공용 사서함 등 **여러 계정이 로그인되어 있고 기본 계정이 아닌 쪽**을 쓰려면,
  Outlook 폴더 트리 최상단에 보이는 이름(예: `"esg@company.com"`)을 적으세요.

#### `customers` — 고객사 목록과 발신 도메인 매핑

**최초 1회만 직접 입력하면, 이후 고객사 구분은 자동입니다.** 동작 방식:

1. 메일 발신자 주소의 도메인(@ 뒷부분)을 `domains`와 대조해 **코드가 자동 매칭**합니다.
   예: `john.doe@apple.com` → domains에 `"apple.com"`이 있는 고객사로 분류.
   하위 도메인(`mail.apple.com`)도 자동 인식합니다.
2. 도메인이 목록에 없으면 LLM이 메일 본문·서명에서 고객사명을 추정합니다.
   (단, 목록에 있는 이름과 일치할 때만 채택)
3. 그래도 판단이 안 되면 `미분류`로 표시됩니다 → 대시보드에서 확인 후 목록에 도메인을 추가하세요.

```json
"customers": [
  { "name": "Apple",   "domains": ["apple.com"] },
  { "name": "Google",  "domains": ["google.com"] },
  { "name": "Dell",    "domains": ["dell.com", "dellteam.com"] }
]
```

`name`은 대시보드·트래커에 표시될 이름이므로 사내에서 부르는 명칭으로 적으면 됩니다.
한 고객사가 여러 도메인으로 보내면 `domains` 배열에 모두 나열하세요.

#### `dept_contacts` — 부서별 데이터 요청 수신자

데이터가 없는 요구사항이 나오면 LLM이 **이 목록에 있는 부서명 중에서** 담당부서를 추정하고,
부서요청 초안의 수신자에 해당 주소를 채웁니다.

```json
"dept_contacts": {
  "환경안전팀": "esh-lead@company.com",
  "인사팀": "hr-esg@company.com"
}
```

- 부서명은 사내에서 실제 쓰는 이름으로 적으세요 (LLM에게 이 목록이 후보로 전달됩니다).
- 주소를 빈칸으로 두면 초안의 수신자가 비워진 채 저장되고, 발송 전에 직접 입력하면 됩니다.

#### `urgency` / `llm`

- `urgency`: 긴급도 판정 기준(기본: 마감 D-7 이내 긴급, D-30 이내 보통). 보통 수정 불필요.
- `llm.max_body_chars`: LLM에 전달할 메일 본문 최대 길이. 사내 LLM 컨텍스트 제한에 맞춰 조정.

### 3) Factsheet 준비

**`data/factsheet_template.xlsx`를 복사해 `data/factsheet.xlsx`로 저장한 뒤 실데이터를
입력하세요.** 템플릿에는 열 설명(2행)과 예시 행 3개(회색 이탤릭)가 들어 있습니다 —
예시 행은 지우고 쓰시면 되고, 설명 행은 남겨두어도 변환 시 자동으로 제외됩니다.
`category`(E/S/G)와 `public_yn`(Y/N) 열은 드롭다운으로만 입력됩니다.

> 실데이터가 담긴 `factsheet.xlsx`는 대외비가 포함될 수 있어 git에 커밋되지 않습니다
> (.gitignore 등록). 템플릿만 저장소에 포함됩니다.

1. 스키마 (사람이 유지보수하는 원본). **꼭 채워야 하는 열은 3개**
   (`item_name`, `value`, `public_yn`)이고 나머지는 비워도 동작합니다:

   | 컬럼 | 필수 여부 | 설명 |
   |------|-----------|------|
   | **item_name** | **필수** | 지표명 — LLM이 고객 요구와 대조하는 기준 |
   | **value** | **필수** | 값 — 답변 초안에 그대로 인용됨 |
   | **public_yn** | **필수** | `Y`만 포함됨. 비우면 안전하게 제외 (N과 동일) |
   | unit | 권장 | 단위 — 없으면 초안에 숫자만 인용되어 오해 소지 |
   | year | 권장 | 기준연도 — 고객이 요구하는 연도와 대조에 사용 |
   | source | 권장 | 출처 — 답변 신뢰도·증빙 대비 |
   | item_code | 선택 | 지표 고유코드. **비우면 변환 시 `AUTO-001`식 자동 부여** |
   | category | 선택 | E/S/G 대분류 (조회 편의용) |
   | site | 선택 | 사이트 (`이천`/`전사` 등) |
   | note | 선택 | 비고 |

2. agent용 사본 생성 (xlsx 수정 시마다 재실행):
   ```
   python tools\xlsx_to_md.py
   ```
   `factsheet.md`(LLM용)와 `factsheet.json`(대시보드 보유정보 표시용)이 생성되며,
   실행 결과에 "제외 N행" 수가 표시되므로 대외비 필터링 여부를 확인할 수 있습니다.

   형식 확인용 가짜 데이터가 필요하면 `python tools\make_sample_factsheet.py`로 샘플을 만들 수 있습니다.

## 실행

### 방법 A — 웹 대시보드 (권장): 기간 지정 + [분석 시작] 버튼

```
run_dashboard.bat
```

브라우저에 제어 화면이 열립니다 (`http://127.0.0.1:8765`, **내 PC 안에서만 접근 가능**).
분석할 메일의 **수신 시작일~종료일을 달력에서 지정**하고 **[분석 시작]**을 누르면
진행률 바가 표시되고, 완료되면 검토 대시보드가 새 탭으로 열립니다.

#### 💬 대응 현황 문답 챗봇 (검토 대시보드 우측 사이드바)

검토 대시보드 **우측 하단의 💬 버튼**을 누르면 사이드바가 열리고, 요청 목록을 보면서
사내 LLM 기반 챗봇에게 자연어로 질문할 수 있습니다. "이번 주 마감 임박 요청은?",
"OO 고객이 요청한 항목 진행상황 알려줘", "Scope 1 요청 이력 보여줘" 같은 질문에 답합니다.

> 챗봇은 대시보드를 서버로 열었을 때(`run_dashboard.bat` → [검토 대시보드])만 동작합니다.
> `output/report_*.html` 파일을 직접 더블클릭해 열면 리포트 열람은 되지만
> 챗봇은 안내 문구만 표시됩니다.

챗봇이 근거로 삼는 데이터 (이 밖의 내용은 답하지 않도록 설계됨):
- `output/tracker.xlsx` — 누적 요청 이력과 **사용자가 수기로 적은 처리상태/비고**
  (관리대장에 처리상태를 기입해 둘수록 "처리 안 된 건" 같은 질문의 답이 정확해집니다)
- `work/analyzed/` — 최근 분석 상세 (요약·요구사항 상태·리스크 검토·초안 유무)
- `data/factsheet.md` — 보유 데이터 (공개가능 항목만 — 대외비는 여기서도 제외)

챗봇은 **조회·설명 전용**입니다. 메일 발송·데이터 수정 등 어떤 동작도 수행하지
않으며, 그런 요청을 받으면 담당자가 직접 하도록 안내합니다.
컨텍스트 예산은 `config.json`의 `llm.chat_max_context_chars`로 조정합니다
(이력이 예산을 넘으면 오래된 것부터 생략).

### 방법 B — 배치 실행 (스케줄러/명령행)

```
run_agent.bat                              전체 실행
run_agent.bat --since 2026-07-01 --until 2026-07-10   수신 기간 지정
run_agent.bat --no-browser                 리포트 자동 오픈 없이 (스케줄러용)
run_agent.bat --limit 10                   최대 10건만 수집
run_agent.bat --skip-collect               수집 생략, 기존 미처리 JSON 재분석
run_agent.bat --no-drafts                  Outlook 초안 저장 생략
```

매일 08:30 자동 실행 등록: `tools\register_task.bat`

두 방법 모두 시작 시 LLM 연결을 먼저 확인하며, **연결 실패 시 아무 분석도 하지 않고 즉시
종료**합니다. 메일 1건 분석이 실패해도 전체는 계속 진행되고, 실패 건은 리포트에 `ERROR`로
표시된 뒤 다음 실행에서 자동 재시도됩니다.

## 산출물 사용법

### `output/report_YYYYMMDD.html` — 검토 대시보드
- 상단 KPI: 신규 요청 / 긴급 / 즉답 가능 / 부서협조 필요 / **고위험 리스크** / 분석 실패
- 고객사별 카드, 카드 안은 요구사항마다 ①요청내용 → ②보유정보(값·출처) →
  ③초안(복사 버튼) → ④리스크 검토(심각도 배지 + 권고 대응) 순서로 배치
- 단일 파일이므로 사내망 오프라인에서 그대로 열립니다.

### `output/tracker.xlsx` — 누적 관리대장
- 실행할 때마다 **신규 행만 추가**됩니다 (기존 행은 절대 수정·삭제되지 않음).
- `처리상태(수기)`, `비고(수기)` 열은 사용자가 직접 기입하며 재실행 시에도 보존됩니다.
- 마지막 `mail_id(시스템)` 열은 중복 방지용 키이므로 수정하지 마세요.

### Outlook 임시보관함 초안
- 제목이 `[AI초안] `으로 시작하는 초안이 저장됩니다.
- 고객 답변 초안은 수신자가 비어 있고, 부서요청 초안은 `config.json`의 담당자 주소가 채워집니다.
- 모든 초안 본문 최상단에 `⚠️ [AI 생성 초안 — 발송 전 반드시 검토 필요]` 배너가 있습니다.
- **검토·수정 후 사용자가 직접 발송하세요.**

## 상태 파일

| 경로 | 용도 |
|------|------|
| `work/inbox/` | 수집된 메일 원문 JSON |
| `work/analyzed/` | 분석 결과 JSON (리스크 검토 포함) |
| `work/processed_ids.json` | 처리 완료 메일 ID (중복 처리 방지). 특정 메일을 다시 처리하려면 해당 ID를 삭제 |
| `logs/YYYYMMDD.log` | 일자별 실행 로그 |

## 테스트

Outlook이 필요 없는 로직(추출 규칙, 대외비 필터, 트래커 보존, 부분 실패, 리스크 검토,
웹 대시보드 실행 흐름, 금지 코드 검사)은 로컬 목 LLM 서버로 자동 검증됩니다:
```
python tests\run_tests.py
```

## 설계 제약 (작업지시서 §0)

| # | 제약 |
|---|------|
| C1 | 메일 자동 발송 금지 — 초안은 임시보관함 저장까지만 |
| C2 | 외부 인터넷 통신 금지 — 사내 LLM 엔드포인트만 호출, `urllib` 표준 모듈만 사용. 웹 대시보드도 127.0.0.1 전용 |
| C3 | 원본 메일·파일 삭제/이동/읽음처리 금지, tracker 덮어쓰기 금지 |
| C4 | `public_yn = N` 데이터는 어떤 출력물에도 미포함 (변환 단계에서 원천 제외) |

## 운영 전 확인 필요 사항 (작업지시서 §9 — 미확정)

아래 항목은 담당자 확인 후 `config.json` 등에 반영해야 합니다. 현재는 플레이스홀더 상태입니다.
