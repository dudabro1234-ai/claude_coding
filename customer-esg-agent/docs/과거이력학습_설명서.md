# 과거 고객대응이력 학습 — 설명서

> 대상 독자: ESG 대응 Agent를 운영하는 담당자.
> 이 문서만 읽으면 이력 학습을 셋업하고, 어디에 어떻게 반영되는지 알 수 있습니다.
> (사내에서 소스를 튜닝 중이어도 이 기능은 `history_index.py` /
> `tools/history_ingest.py` 두 파일 + 각 모듈의 연결 지점 몇 곳으로 구성되어
> 있어, 문서 하단 "구성 파일" 절을 참고해 이식할 수 있습니다.)

---

## 1. 이건 무슨 기능인가

과거에 고객 요청에 **실제로 어떻게 답변했는지**(요청 ↔ 발송 답변 쌍)를 시스템에
넣어두면, 신규 요청이 왔을 때:

- 비슷한 과거 요청을 자동으로 찾아 **화면에 나란히 보여주고**,
- 답변 초안을 **과거에 보낸 답변의 어조·형식·내용과 일관되게** 작성하며,
- 과거 답변과 이번 데이터가 다르면 **리스크로 경고**합니다.

"학습"이라고 부르지만 모델을 재훈련하는 것이 아닙니다. 이력을 **검색 가능한
인덱스로 변환**해 두고, 매 분석 때 관련 이력만 골라 사내 LLM 프롬프트에 함께
넣는 방식(검색 증강)입니다. 그래서:

- 이력 파일을 **갈아끼우면 즉시 반영**됩니다 (재훈련·재배포 없음)
- 이력 데이터는 **사내 LLM 호출 외에는 어디로도 나가지 않습니다**

---

## 2. 사용자가 해야 할 일 (셋업 3단계)

### 단계 1 — 이력 엑셀 준비

과거 대응 기록을 엑셀 1개로 모읍니다. **필수 열은 4개**뿐이고, 열 이름이 정확히
일치하지 않아도 아래 별칭이면 자동 인식됩니다:

| 필드 | 인식되는 열 이름(별칭) | 내용 |
|---|---|---|
| 일자 (필수) | 일자, 날짜, 대응일, 답변일, 회신일, 수신일 | YYYY-MM-DD 권장 |
| 고객사 (필수) | 고객사, 고객, 고객명 | **config.json의 고객사명과 동일하게** — 그래야 "동일 고객" 연계가 정확해집니다 |
| 요청내용 (필수) | 요청내용, 요구사항, 요청사항, 질문, 문의내용 | 고객이 요청한 내용 |
| 답변내용 (필수) | 답변내용, 회신내용, 답변, 회신, 대응내용 | **실제 발송한 답변** 전문 또는 요지 |
| 요청유형 (선택) | 요청유형, 유형, 구분 | 설문/데이터제출 등 |
| 프레임워크 (선택) | 프레임워크, 양식 | CDP, EcoVadis 등 |
| 담당자 (선택) | 담당자, 담당 | |
| 비고 (선택) | 비고, 결과, 메모, 처리결과 | "기한 내 제출", "감사 통과" 등 결과 |

빈 양식이 필요하면:
```
python tools\history_ingest.py --make-template
```
→ `data\history_template.xlsx` 생성 (예시 행 포함).

**작성 팁**
- 답변내용은 전문일수록 좋습니다 — 초안의 어조·형식이 여기서 나옵니다.
- 한 메일에 요청이 여러 개였다면 요청 단위로 행을 쪼개는 편이 검색이 잘 됩니다.
- 결과(비고)를 적어두면 "그때 어떻게 마무리됐는지"까지 화면에 표시됩니다.

### 단계 2 — 파일 넣고 인덱싱

```
1) 엑셀을 data\history_drop\ 폴더에 넣는다
2) python tools\history_ingest.py        ← 가장 최근 파일을 자동 선택
```
실행하면 `data\history_index.json`(검색 인덱스)이 생성되고 "레코드 N건"이
표시됩니다. 특정 파일을 지정하려면 경로를 인자로 주면 됩니다.

### 단계 3 — 갱신 (운영 습관)

- 새 대응이 끝날 때마다 엑셀에 행을 추가하고 **단계 2를 다시 실행**하면 끝.
- 자동 실행되는 것이 아니므로, 월 1회 등 주기를 정해 갱신하는 것을 권장합니다.
- 참고: 시스템이 만드는 `output\tracker.xlsx`(관리대장)는 "요청 접수/상태" 기록이고,
  이력 엑셀은 "발송한 답변 원문" 기록입니다. 장기적으로는 tracker에 답변 요지
  열을 추가해 한 파일로 합치는 운영도 가능합니다.

## 3. 학습 결과가 어디에 어떻게 쓰이나

### ① 검토 대시보드 — "③ 관련 과거 대응 이력" 섹션

메일 상세 화면(①요청 → ②보유정보 → **③과거이력** → ④초안 → ⑤리스크)에서:

- 요구사항별 유사 이력 + **같은 고객의 최근 커뮤니케이션**을 최대 6건 표시
- 각 항목: 일자 · 고객사 · [동일 고객 / 타 고객 참고] 배지 · 당시 요청 발췌 ·
  **"당시 발송 답변 보기"**(전문 펼침) · 결과(비고)

### ② 답변 초안 생성

관련 이력이 초안 LLM 호출에 함께 전달되어, 프롬프트 규칙(`prompts/draft.txt`
7~9번)에 따라:

- **같은 고객** 이력 → 어조·형식·상세 수준을 맞추고, 이어지는 요청이면
  "지난 회신에서 안내드린 바와 같이" 같은 연결 표현 사용
- 과거 답변 수치와 이번 데이터가 다르면 → 임의로 설명을 만들지 않고
  **⑤ 리스크 검토에 '일관성' 항목으로 표시** (발송 전 사유 확인 유도)
- **타 고객** 이력 → 표현·구성 참고만. 타 고객사명이나 그 고객에게만 제공한
  수치를 새 답변에 옮기는 것은 프롬프트로 금지

### ③ 챗봇 (대시보드 우측 사이드바)

"작년에 A고객에 Scope 1 뭐라고 답했지?", "EcoVadis 설문 대응했던 내용 찾아줘"
같은 질문에 이력을 검색해 날짜·고객·당시 답변을 인용해 답합니다.

## 4. 내부 동작 (어떻게 찾아내나)

1. `tools/history_ingest.py`가 엑셀을 레코드(JSON)로 정규화 → `history_index.json`
2. 분석 시 `history_index.py`가 **키워드 검색**을 수행:
   - 요구사항 문장에서 2글자 이상 토큰 추출 (상투어 제외: "데이터", "요청" 등)
   - 이력의 고객사/유형/프레임워크/요청/답변 텍스트와 대조해 겹치는 수로 점수화
   - **같은 고객사면 가점** → 동일 고객 이력이 우선 노출
   - 키워드 매칭과 별개로 같은 고객의 **최근 2건**은 항상 함께 표시 (맥락 유지)
3. 선정된 이력만 LLM 프롬프트에 들어갑니다 (전체 이력을 넣지 않으므로
   이력이 수천 건이어도 컨텍스트를 넘치지 않음. 답변은 건당 800자로 절단)

> 한계: 현재는 키워드 기반이라 표현이 완전히 다른 유사 요청(예: "탄소배출" vs
> "GHG")은 놓칠 수 있습니다. 정확도가 아쉬우면 사내 LLM으로 이력에 표준 태그를
> 붙이는 전처리 단계를 추가하는 확장이 가능합니다 (요청 시 구현).

## 5. 보안·주의사항

| 항목 | 내용 |
|---|---|
| 데이터 반출 | 이력 원본(`history_drop/`)과 인덱스(`history_index.json`)는 고객 커뮤니케이션 원문 → **git 커밋 차단**(.gitignore), 외부 전송 금지 |
| 고객 간 격리 | 타 고객 이력은 "표현 참고"로만 쓰도록 프롬프트 강제. 그래도 **초안 발송 전 검토는 필수** (모든 초안 공통 원칙) |
| 이력의 자격 | 여기 넣는 답변은 "이미 그 고객에게 발송된 내용"이어야 합니다. 발송 전 초안이나 내부 검토 의견을 넣지 마세요 |
| 삭제 | 특정 이력을 빼고 싶으면 엑셀에서 행 삭제 후 재인덱싱 |

## 6. 구성 파일 (튜닝본에 이식할 때)

| 파일 | 역할 | 이식 방법 |
|---|---|---|
| `tools/history_ingest.py` | 엑셀 → 인덱스 변환 + 템플릿 생성 | 그대로 복사 (독립 실행) |
| `history_index.py` | 인덱스 로드·검색 | 그대로 복사 (독립 모듈) |
| `analyzer.py` | `find_history_matches()`, `_history_prompt_block()` 함수 2개 + 결과 dict에 `history_matches` 추가 + 초안 호출 직전 블록 삽입 | 함수 2개 복사 후 초안 프롬프트 조립부에 `history_block` 연결 |
| `prompts/draft.txt` | 이력 활용 규칙 7~9번 | 해당 문단 복사 |
| `reporter.py` | `_history_html()` 함수 + 카드 렌더에 1줄 + `.hist*` CSS | 함수·CSS 복사 |
| `chatbot.py` | `history_context()` 함수 + `chat()`에 2줄 | 함수 복사 |
| `prompts/chat.txt` | 이력 인용 규칙 6번 | 해당 문단 복사 |
| `.gitignore` | `data/history_drop/*`, `data/history_index.json` | 항목 추가 |

## 7. 문제 해결

| 증상 | 원인/조치 |
|---|---|
| "필수 열을 찾지 못했습니다" | 열 이름이 별칭 목록에 없음 → 열 이름 변경 또는 템플릿 사용 |
| ③ 섹션이 안 보임 | ① 인덱싱을 안 했거나 ② 관련 이력이 실제로 없음. `data\history_index.json` 존재·건수 확인 |
| 엉뚱한 이력이 잡힘 | 요청내용이 너무 짧거나 상투어 위주 → 이력의 요청내용을 구체적으로 보완 |
| 동일 고객인데 "타 고객 참고"로 표시 | 이력 엑셀의 고객사명이 config.json의 고객사명과 다름 → 표기 통일 |
